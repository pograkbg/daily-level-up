# 예문 설계 (Tatoeba 기반)

## 1. 목표
- 영어 퀴즈에서 단어마다 **짧고 쉬운 예문 여러 개**를 보여 준다.
- 하루에도 같은 아이에게 같은 예문이 반복되지 않게 한다.
- **실행 중에는 외부 API를 호출하지 않는다.** 예문은 미리 받아서 우리 DB에 저장한다.

## 2. 원칙
| 원칙 | 이유 |
|---|---|
| 런타임 외부 호출 없음 | 응답 속도, 서비스 변경, 요청 제한에서 자유로움 |
| 예문은 행 단위로 출처 저장 | 라이선스 표기(CC BY)를 예문마다 정확히 보여 주기 위해 |
| 하루 선택은 우리 쪽에서 결정 | `sort=random`은 수집 때만 쓰고, 중복 제외는 DB에서 처리 |
| 승인된 예문만 노출 | 부적절하거나 어려운 문장을 관리자가 숨길 수 있게 |

## 3. Tatoeba API 사용 방식 (수집 단계에서만)
확인한 응답 구조 (`/v1/sentences`):
- `data[]`: `id`, `text`, `lang`, `license`, `owner`, `translations[]`
- `translations[]`: `id`, `text`, `lang`, `license`, `owner`
- `paging`: `total`, `has_next`, `next` (커서 방식, `after=` 값으로 다음 페이지)

수집 호출 예:
```
https://api.tatoeba.org/v1/sentences?lang=eng&trans:lang=kor&showtrans:lang=kor&sort=random&limit=100
```
- `sort=random`은 여러 번 받을 때 다른 문장을 섞어 주므로 **수집 풀을 넓히는 데만** 쓴다.
- 수집은 개발자 PC에서 스크립트로 한 번씩 돌린다. 호출 사이에 1초 이상 쉰다.
- `paging.next`를 따라가며 필요한 개수에 도달하면 멈춘다.

## 4. 수집 기준 (스크립트에서 필터)
1. 영어 문장이 **8단어 이하**, 한국어 번역이 **25자 이하**
2. 영어 문장에 우리 단어 목록(800개) 중 하나가 **단어 경계로** 들어 있음 (예: `apple`은 `applesauce`에 매칭하지 않음)
3. `is_unapproved = false`
4. `license`가 **CC BY 계열**인 것만 (비상업 전용 NC 라이선스는 제외)
5. 금칙어 목록(욕설·폭력 등)이 없음
6. 같은 단어에 예문은 **최대 5개**까지만 저장 (너무 많으면 풀 관리가 어려움)

결과는 DB에 넣기 전에 **미리보기 파일(CSV)**로 저장해서 사람이 훑어볼 수 있게 한다.

## 5. DB 설계

### 5-1. `english_examples` (예문 풀)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | bigserial, PK | 내부 번호 |
| tatoeba_en_id | bigint, unique | 영어 문장 번호 (중복 수집 방지) |
| tatoeba_ko_id | bigint | 한국어 문장 번호 |
| word_id | integer, FK → english_words | 어떤 단어의 예문인지 |
| en | text | 영어 문장 |
| ko | text | 한국어 번역 |
| owner | text | 작성자 (Tatoeba 표시명) |
| license | text | 예: `CC BY 2.0 FR` |
| approved | boolean, default true | 관리자가 숨길 수 있게 |
| created_at | timestamptz | 수집 시각 |

인덱스: `(word_id) where approved`

RLS: 로그인 사용자 **읽기만** 허용. 쓰기는 수집 스크립트(SQL)와 관리자만.

### 5-2. `english_example_views` (아이별 노출 기록)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| child_id | uuid, FK | 아이 |
| example_id | bigint, FK | 예문 |
| shown_on | date | 노출한 날짜 (서울 기준) |
| PK | (child_id, example_id, shown_on) | 같은 날 중복 방지 |

RLS: 본인 아이 기록만 읽고 쓰기. 기록은 보관 기간을 두고 오래된 것은 정리한다(예: 60일).

## 6. 하루 예문 선택 규칙 (DB 함수, `pick_examples`)
입력: `child_id`, `word_id`, `today`, `limit`(기본 2)

순서:
1. **오늘 이미 보여 준 예문은 제외** (`english_example_views`에서 `shown_on = today`)
2. **최근 30일 안에 본 예문은 뒤로** 보낸다 (아직 안 본 것을 먼저)
3. 남은 후보를 `md5(child_id || today || example_id)` 순으로 정렬해서 고른다
   - 같은 아이·같은 날이면 결과가 항상 같다 (새로고침해도 안 바뀜)
   - 날짜가 바뀌면 순서가 바뀐다
4. 고른 예문을 `english_example_views`에 기록한다

후보가 없으면:
- 기존 `english_words.example_en/example_ko`를 대신 보여 준다.
- 출처는 "교육과정 단어 목록 자료"로 표시한다.

## 7. 앱 화면 연결
- 퀴즈 해설 영역에 예문 1개를 기본으로 보여 주고, "다른 예문" 버튼으로 다음 후보를 연다.
- 예문 아래에 출처를 작게 표시한다:
  `예문 출처: Tatoeba · CC BY 2.0 FR · 작성자 ○○`
- 퀴즈 화면 하단 출처 영역에도 Tatoeba 링크를 둔다.

## 8. 관리자 기능 (나중 단계)
- 관리자 화면에서 예문 목록을 보고 `approved`를 끌 수 있게 한다.
- 숨긴 예문은 선택 후보에서 빠진다.

## 9. 갱신 주기
- 수집 스크립트는 **분기마다 한 번** 돌린다.
- 새로 받은 예문만 `tatoeba_en_id` 기준으로 추가한다 (기존 것은 건너뜀).
- 이미 저장한 예문의 라이선스나 내용이 바뀌었는지도 함께 확인한다.

## 9-1. 갱신 방식 (확정 방향)
- **1단계:** 수집 스크립트를 개발자 PC에서 수동 실행한다. 실행 결과 요약(추가·숨김·부족 단어)을 확인한다.
- **2단계:** 관리자 화면에 마지막 갱신 시각, 추가·숨김 개수, 부족 단어 목록을 표시한다. "갱신 요청" 버튼은 작업을 **요청만** 기록하고, 실제 수집은 별도 작업이 처리한다.
- **3단계:** 분기별 자동 실행을 붙인다. 실행 환경은 나중에 정한다.

갱신 규칙:
- 이미 있는 문장은 Tatoeba 문장 번호로 중복을 확인해 건너뛴다.
- 단어당 10개를 넘으면 가장 적게 보인 예문부터 `approved = false`로 숨긴다. 삭제하지 않으므로 기록은 남는다.
- 라이선스가 CC BY 계열이 아니게 바뀐 문장은 자동으로 숨긴다.
- 새 문장을 고를 때는 `sort=random`을 쓰고, 아이에게 보여 주는 순서는 아이·날짜 기준으로 섞는다.

## 10. 상업화 시 확인할 것
- 예문마다 라이선스가 다를 수 있으므로 행 단위로 저장하고 화면에 표시한다.
- CC BY 계열은 출처 표기가 필요하다. NC(비상업) 라이선스 문장은 수집하지 않는다.
- Tatoeba 이용 약관과 저작자 표시 방식은 공식 사이트에서 최신 내용을 확인한다.

## 11. 작업 순서 (제안)
1. 수집 스크립트 작성 및 미리보기 CSV 생성

3. 수집 결과 SQL 실행 → 개수와 샘플 확인

6. 관리자 예문 숨기기 (선택 사항)
